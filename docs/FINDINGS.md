# Findings so far (15 Nov 2026)

Written by hand from the tables in [RESULTS.md](RESULTS.md) (generated by `scripts/summarise.py`).
Two models, one pass each: `gemini-3.5-flash-lite` and a local `Qwen2.5-Coder-7B` (4-bit, MLX).
750 answers per model: 150 questions x 5 setups. Read the limits at the end before quoting anything.

## 1. Cleaning the data is the biggest single step

| | Gemini correct | Gemini silently wrong | Qwen 7B correct | Qwen 7B silently wrong |
|---|---:|---:|---:|---:|
| Raw data, schema only | 22.9% | 75.7% | 20.0% | 77.1% |
| Cleaned tables, schema only | 92.9% | 7.1% | 77.1% | 11.4% |

Same questions, same prompt, same models. Only the tables changed.

On the 106 "trap" questions (where the obvious query on raw data gives a different number),
Gemini was right 0 times out of 106 on raw data and Qwen once. On the 34 questions where raw
and cleaned data agree, Gemini scored 94.1% on raw data. So the models are not bad at SQL on
raw data; they are answering a different question, correctly, on dirty rows.

87.7% of Gemini's silent errors on raw data (93 of 106) are exactly the number the obvious raw
query returns. The model did what a careless analyst would do.

**Honest caveat.** Part of this is true by construction: the gold answer is defined on cleaned
data, and a model that is shown only raw column names cannot know the cleaning rules. The
useful part is the size of the effect and the next finding.

## 2. Documentation did not make up for skipping the cleaning

The extra arm gave the models the raw table plus full docs: the data dictionary, the 7 cleaning
rules and the metric definitions. Trap questions only:

| | Correct | Silently wrong | Error |
|---|---:|---:|---:|
| Gemini, raw | 0.0% | 98.1% | 1.9% |
| Gemini, raw + docs | 14.2% | 51.9% | 34.0% |
| Gemini, cleaned | 93.4% | 6.6% | 0.0% |
| Qwen 7B, raw | 0.9% | 95.3% | 3.8% |
| Qwen 7B, raw + docs | 1.9% | 92.5% | 5.7% |
| Qwen 7B, cleaned | 84.9% | 9.4% | 5.7% |

- Gemini **tried** to apply the rules in every query, and mostly failed: 41 SQL errors, most
  from rule 7 (it has to pull the month out of the file name and got the text position wrong),
  and many wrong numbers from applying some rules but not all.
- Gemini's docs even hurt on the easy questions: on non-trap questions it fell from 94.1%
  correct (raw) to 29.4% (raw + docs).
- Qwen 7B largely **ignored** the rules: 71.4% of its silent errors with docs are still the
  naive raw number.

In this experiment, telling the model the rules was not a substitute for applying them once
in a pipeline. This is the result that answers the "dirty data obviously gives wrong answers"
objection: the question is not whether dirt hurts, but whether documentation can fix it. Here
it could not.

## 3. Docs on top of cleaned tables: a small, consistent gain

| | Gemini correct | Gemini silently wrong | Qwen 7B correct | Qwen 7B silently wrong |
|---|---:|---:|---:|---:|
| Cleaned, schema only | 92.9% | 7.1% | 77.1% | 11.4% |
| Cleaned + docs | 98.6% | 1.4% | 82.9% | 6.4% |

About 6 points for both models, and the silent-error rate drops for both. The gain is largest
on level-3 questions for Gemini (82.9% to 100%). With one pass per model, a gap this size on
140 questions should be confirmed with the repeat runs before it is called solid.

## 4. The semantic layer did not beat the docs. The hypothesis is not supported.

Same information in both, by construction.

| Questions | Model | Docs: correct / silent / error | Semantic layer: correct / silent / error |
|---|---|---|---|
| Expressible in the layer (108) | Gemini | 99.1% / 0.9% / 0.0% | 91.7% / 0.9% / 7.4% |
| Expressible in the layer (108) | Qwen 7B | 89.8% / 2.8% / 7.4% | 64.8% / 9.3% / 25.9% |
| Not expressible (32) | Gemini | 96.9% / 3.1% / 0.0% | 0.0% / 65.6% / 34.4% |
| Not expressible (32) | Qwen 7B | 59.4% / 18.8% / 21.9% | 0.0% / 31.2% / 68.8% |

- **Where the layer can express the question,** it matched the docs on silent errors for Gemini
  (0.9% both) but added loud errors, and for the small local model it was clearly worse.
  The main cause is one mistake: writing a month filter as `'2023-01'` where the layer needs a
  full date (9 of Gemini's errors, 35 of Qwen's). The errors are loud, not silent.
- **Where the layer cannot express the question** (percent shares, "top zone in each borough",
  daily statistics, percentiles), the models almost never said so. They returned something
  else instead. Text-to-SQL with docs handled these fine.
- **Important nuance about those "silent errors".** Most are not wrong numbers. The model
  returned correct ingredients (for "what percentage of trips were paid by card" it returned
  the trip count per payment type) but not the number that was asked. The grader counts that as
  a silent error because the question was not answered. A stricter analysis should split
  "correct ingredients" from "wrong number" (for example ignoring a "zones with at least 10,000
  trips" condition, which also happened). That split is not done yet.

So on this benchmark the semantic layer's promise (it cannot write wrong SQL) held only inside
its coverage, and there it only tied the docs for the stronger model. Its cost was coverage and
interface mistakes. The instructions I gave for the layer's query format were short; a longer
guide with a month-filter example would likely remove many of the loud errors. That is a
limitation of this study, and it should be said in the paper.

## 5. Questions the data cannot answer

10 questions (no driver IDs, no cash tips, no ratings, ...). Correct means the model refused.
Gemini refused 8 to 10 of 10 depending on the setup, with 10 of 10 given cleaned tables + docs.
Qwen 7B refused 4 to 8 of 10 and often invented an answer. With only 10 questions these are
indications, not rates.

## 6. Model size

Qwen 7B is level with Gemini on easy questions on cleaned data (100% on level 1) and falls
behind as questions get harder (57 to 60% on level 3 against 83 to 100%). The ordering of the
setups is the same for both models, which is the more important point: the conclusions above
do not depend on which of the two models is used.

## What the data says about the research question

"Where does the accuracy come from: the model, the documentation, or the data engineering?"

On this dataset: **mostly from the data engineering** (about +57 to +70 points), then the model
(up to about 15 points between the two models on cleaned data), then documentation (about +6
points on top of cleaned data, and no rescue for raw data). A compiled semantic layer did not
add accuracy over equally informative docs.

## Limits (read before quoting)

- **One pass per model.** Gemini's repeats 2 and 3 are not run yet (API quota), so there is no
  run-to-run noise estimate. Differences of a few points may be noise.
- **All 150 questions were written by Claude** and are not yet reviewed by the project owner.
  None were written blind. The author knew the data problems and the metric list.
- **The raw-vs-cleaned gap is partly true by construction** (see finding 1).
- **One dataset, two models** (one small cloud model, one 7B local model), temperature 0, one
  attempt per question with no repair loop. A repair loop would likely fix many loud errors.
- **Semantic-layer instructions were brief**, and "correct ingredients" are graded as silent
  errors (see finding 4).
- **One correction after the run:** 6 Gemini replies that said CANNOT_ANSWER inside a code
  block were first recorded as blocked SQL; they are now graded as refusals
  (`scripts/regrade_refusals.py`). No other grading rule was changed after the models ran.
- Qwen 3B has not been run.
